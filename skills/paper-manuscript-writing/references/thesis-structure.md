# 毕业论文六阶段详细指令

## 阶段 1：选题分析

### 输入
- 毕业设计任务书（PDF/DOCX/文本）
- 或论文题目字符串

### 分析框架

**1.1 题目解构**
- 提取关键词（3-5个）
- 识别研究对象（什么系统/什么问题）
- 识别技术方法（用什么技术/什么方法解决）
- 识别约束条件（任务书中的具体要求）

**1.2 技术定位**
- 该题目属于哪个技术领域
- 核心技术栈识别（编程语言、框架、协议）
- 技术难度评估（哪些部分有现成方案，哪些需要设计）

**1.3 章节建议**
基于题目类型建议论文结构：

类型A — 系统设计类（如"XX系统的设计与实现"）：
```
第1章 绪论
第2章 相关技术介绍
第3章 系统需求分析
第4章 系统设计
第5章 系统实现
第6章 系统测试
第7章 总结与展望
```

类型B — 算法/模型类（如"基于XX的YY方法研究"）：
```
第1章 绪论
第2章 相关工作
第3章 方法设计
第4章 实验设计
第5章 实验结果与分析
第6章 总结与展望
```

类型C — 硬件/嵌入式类（如"基于XX的YY控制系统设计"）：
```
第1章 绪论
第2章 相关技术介绍
第3章 系统总体方案设计
第4章 硬件设计
第5章 软件设计
第6章 系统调试与测试
第7章 总结与展望
```

**1.4 风险点识别**
- 数据获取：是否需要采集实验数据？来源？
- 技术可行性：是否有超出本科水平的技术要求？
- 工作量评估：是否可在规定时间内完成？

### 输出格式
```markdown
# 选题分析：[论文题目]

## 1 题目解构
### 1.1 关键词
### 1.2 研究对象
### 1.3 技术方法
### 1.4 任务书要求摘要

## 2 技术定位
### 2.1 所属领域
### 2.2 核心技术栈
### 2.3 难度评估

## 3 建议章节结构

## 4 风险与准备事项
### 4.1 数据准备
### 4.2 环境搭建
### 4.3 时间规划建议
```

## 阶段 2：开题报告

### 输入
- 阶段1 `topic-analysis.md`
- 用户补充的文献（如有）

### 内容框架

**2.1 选题依据**
- 不写空洞的"意义"，写具体的应用场景和技术痛点
- 引用具体数据或案例说明为什么要做这个题目
- 字数：500-800字

**2.2 国内外研究现状**
- 按技术维度组织（非逐条罗列）
- 每个维度写发展脉络 → 代表工作 → 现存不足
- 最后点明本文切入点
- 字数：1000-1500字
- 注意：只能引用用户提供的真实文献，缺少的标注 `[TODO: 需补充文献]`

**2.3 研究内容与目标**
- 列出3-5个具体研究内容（可量化）
- 预期目标用具体指标衡量
- 字数：300-500字

**2.4 研究方案**
- 技术路线（文字+流程描述，建议用户后续补充流程图）
- 关键技术问题及拟解决方案
- 字数：500-800字

**2.5 进度安排**
- 用表格呈现，按月/周粒度
- 总时长参考任务书要求（通常16-20周）

**2.6 参考文献**
- GB/T 7714 格式
- 至少标注 `[TODO]` 占位符，等用户补充

### 输出格式
标准开题报告 Markdown，含以上所有小节。

---

## 阶段 3：文献综述

### 输入
- 阶段1-2 产物
- 用户提供的参考论文（PDF/链接/手动输入的文献信息）

### 写作策略

**组织方式：** 按主题/技术维度，不按文献逐条。

**每个维度的论述结构：**
1. 该技术/方法的起源与定义（1-2句）
2. 发展脉络：关键节点与代表性工作（综合论述）
3. 当前技术水平（引用最新工作）
4. 局限性与未解决问题
5. 与本文工作的关联

**综述结尾：**
- 用一段话明确指出现有研究的 gap
- 说明本文如何填补或部分填补这个 gap
- 不用"综上所述"

### 质量要求
- 每个引用都必须是用户提供的真实文献
- 同一段落内引用不超过3个（避免堆砌）
- 避免"XX具有XX优点，但也存在XX不足"的模板句式
- 总字数：3000-5000字（视文献数量调整）

---

## 阶段 4：论文正文

### 输入
- 阶段1-3 所有产物
- 用户提供的：代码、截图、实验数据、架构图

### 各章写作指令

**第1章 绪论（2000-3000字）**
- 1.1 研究背景：从具体问题引入，不用"随着...的发展"
- 1.2 国内外研究现状：引用/精简阶段3文献综述
- 1.3 本文主要工作：逐条列出本文的具体贡献
- 1.4 论文组织结构：一段话描述各章内容

**第2章 相关技术（2000-3000字）**
- 只写本设计实际使用的技术
- 每个技术：定义 → 核心原理（简明）→ 为什么选它（对比备选方案）
- 不要写教科书式的知识点罗列
- 不要写自己没有用到的技术

**第3章 系统设计（3000-5000字）**
- 3.1 需求分析：功能需求（表格列出）+ 非功能需求
- 3.2 总体架构：架构图 + 文字说明（图由用户提供或用 Mermaid）
- 3.3 详细设计：按模块展开，每个模块说明功能、接口、数据流
- 3.4 数据库设计：ER图 + 表结构（如适用）

**第4章 系统实现（3000-5000字）**
- 按模块组织
- 每个模块：实现思路 → 关键代码 → 代码说明
- 代码片段由用户提供，不编造
- 代码长度控制在 15-30 行/段，标注文件路径
- 配合截图说明运行效果（截图由用户提供）

**第5章 测试（2000-3000字）**
- 5.1 测试环境：硬件、软件、工具（表格）
- 5.2 功能测试：测试用例表（编号、输入、预期、实际、结果）
- 5.3 性能测试：数据由用户提供，分析数据说明结论
- 5.4 测试总结：覆盖了什么，遗留什么

**第6章 总结与展望（800-1200字）**
- 总结：逐条对应第1章提出的工作
- 展望：2-3个具体的改进方向，不要写空话
- 不用"综上所述"开头

### 图表规范
- 图：`![图 X-Y 图题](path)` → 图题在图下
- 表：表题在表上方，用 Markdown 表格
- 编号：X = 章号，Y = 章内序号
- 首次引用在正文中出现：如"如图 3-1 所示"

### 公式规范
- 使用 LaTeX：`$$公式内容 \tag{X-Y}$$`
- 首次出现的变量在公式下方用"式中："说明

## 阶段 5：查重降重

### 输入
- 阶段4 `thesis-body.md`
- 查重报告（可选，用户提供标红段落）

### 处理流程
详见 `plagiarism-strategy.md`。

### 关键原则
- 不使用同义词替换工具
- 不使用隐形字符、零宽空格等技巧
- 不将文字转为图片来逃避查重
- 所有改写必须保持学术准确性
- 降重后论文的可读性不应低于原文

---

## 阶段 6：格式导出

### 输入
- 阶段4/5 的论文正文
- 用户提供的：中文摘要、英文Abstract、致谢、附录

### 组装顺序
1. YAML 元数据块
2. `<!-- cover -->` 封面占位（Lua filter 处理）
3. `<!-- integrity -->` 学术诚信承诺书
4. `<!-- abstract -->` 中文摘要 + 关键词
5. `<!-- abstract-en -->` English Abstract + Keywords
6. `<!-- toc -->` 目录（pandoc 自动生成）
7. 正文各章节
8. `## 参考文献` + 文献列表
9. `## 致谢`
10. `## 附录`（如有）

### 转换命令
```bash
npx tsx skills/paper-manuscript-writing/scripts/export.ts <项目目录> -o "<output.docx>"
```
