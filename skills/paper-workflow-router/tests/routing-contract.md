# Routing Contract

The router passes when it:

- selects exactly one primary skill for simple requests
- adds supporting skills for mixed requests
- separates academic lanes from out-of-scope software/environment work
- routes "look at this thesis/project folder" to manuscript intake before writing
- routes project-context-only or "continue previous thesis" requests to manuscript intake with context checkpointing
- routes mixed thesis/source/screenshot/defense delivery through the router before specialized lanes
- routes DOCX layout complaints to DOCX repair
- routes reference authenticity and numeric citation sync to literature
- routes real screenshots, CAD, simulation, and test visuals to figure evidence before generation
- routes defense PPT and video/demo requests to paper-to-PPT handoff

It fails if it loads all skills for every task, treats project deployment as paper work, or calls a Markdown slide prompt a finished PPTX.
