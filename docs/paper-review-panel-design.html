Paper Review Panel

多模型 × 多视角审核 — 配置初始化 Skill 设计稿

Status: Draft · 待确认 2026-06-08 · skills/paper-review-panel
这一步做什么

一个配置初始化 skill：让用户选择是否启用多模型多视角审核；启用则配置一个评审面板矩阵（模型端点 × 评审视角）。

范围边界

只做配置与初始化。实际评审执行、重审循环、orchestrator 编排、router 改造 — 均为非目标，后续再做。

目标

吸收竞品（Imbad / ARIS）多模型 + 多视角评审优势，先把承载它的配置契约立稳。

端点实测（2026-06-08，已跑通）

端点模型连通/中文多轮会话实测注意点

结论：多模型 ✓、多视角 ✓、多轮重审 ✓ — “评 → 改 → 再评”在模型层已验证可行。

配置契约 .paper-context/review-panel.yaml

四层结构：① 端点池 → ② 视角库 → ③ 评审矩阵 → ④ 裁决规则

enabled: true            # 总开关：false → 退化为默认单模型单次评审，插件行为不变

# ① 模型端点池（密钥只写环境变量名，绝不写明文）
endpoints:
  minimax:
    base_url: https://api.minimaxi.com/anthropic
    model: MiniMax-M3
    auth_env: MINIMAX_KEY      # 真密钥放环境变量，配置只记名字
    max_tokens: 800
    output: standard
  mimo:
    base_url: https://token-plan-cn.xiaomimimo.com/anthropic
    model: mimo-v2.5-pro
    auth_env: MIMO_KEY
    max_tokens: 1500          # 实测：MiMo 思考长，token 要给大
    output: thinking-first    # 实测：结构非标准，解析走容错

# ② 视角库（prompt 模板放 references/review-lenses/）
lenses:
  rigor:        逻辑严谨 / 夸大表述
  citation:     引用真实 / 数据支撑
  completeness: 结构完整 / 格式

# ③ 评审矩阵：哪个模型 × 哪个视角 = 一个评审员
panel:
  - { endpoint: minimax, lens: rigor,        weight: 2, veto: false }
  - { endpoint: mimo,    lens: citation,     weight: 1, veto: true  }   # 引用硬伤→一票打回
  - { endpoint: minimax, lens: completeness, weight: 1, veto: false }

# ④ 裁决规则
verdict:
  rule: weighted        # 加权投票
  max_rounds: 2         # 最多再评 2 轮

评审面板（默认矩阵）

评审员模型（端点）视角权重否决权
R1 MiniMax-M3 逻辑严谨 / 夸大表述 2 —
R2 mimo-v2.5-pro 引用真实 / 数据支撑 1 ✓ 一票打回
R3 MiniMax-M3 结构完整 / 格式 1 —

只有一个模型也能用：panel 多条复用同一 endpoint、不同 lens，即“单模型多视角”。

初始化流程

1问：启用多模型多视角审核吗？ → 否：写 enabled: false 结束
2是 → 选 一键默认（套用上表）或 手动（加端点 → 选视角 → 配矩阵 → 裁决）
3写 .paper-context/review-panel.yaml
4校验：schema + 环境变量是否存在（警告）+ 明文密钥 → 硬失败
5可选：对每个端点发最小请求做连通性自检

关键决策与边界

  • ▸ 混合式：代码持契约/调度/聚合，LLM 做语义评审
  • ▸ 人在环路优先：插件不持密钥，你用不同 profile 提供评审；自动调 API 为后续扩展
  • ▸ 密钥安全：只存环境变量名，明文密钥直接判失败
  • ▸ 向后兼容：enabled:false 时插件零行为变化
  • ▸ 不动 router：context owner 仍是 paper-manuscript-writing
  • ▸ 可插拔后端：in-session / profile-进程 / 跨厂商，契约预留
